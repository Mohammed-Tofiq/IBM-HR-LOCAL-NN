# Employee Attrition Predictor

A fully local, custom-built neural network that predicts employee attrition risk from HR data — no cloud APIs, no pre-trained models, no external services. Built with PyTorch and trained from scratch.

## Overview

This project analyzes IBM's HR Analytics dataset to identify which employees are at highest risk of leaving, and to surface the factors that most strongly drive attrition. A neural network is trained locally on 1,470 employee records and served through a terminal application for real-time, offline risk scoring.

## Key Results

| Metric | Score |
|---|---|
| Accuracy | 0.82 |
| Precision | 0.42 |
| Recall | 0.69 |
| F1 Score | 0.52 |
| ROC-AUC | 0.80 |

The dataset is imbalanced — only ~16% of employees in the data actually left. A naive model can hit ~84% accuracy by predicting "stay" for everyone, while missing almost all actual leavers. This model uses class-weighted loss specifically to avoid that trap, prioritizing **recall** (catching actual leavers) over raw accuracy, which is the right tradeoff for an early-warning HR tool: better to flag some false positives than to miss someone who's about to resign.

**Top predictor of attrition:** OverTime, by a wide margin, followed by Age and Distance From Home (see `feature_importance.png`).

## How It Works

1. **Data**: `WA_Fn-UseC_-HR-Employee-Attrition.csv` (IBM's public HR Analytics dataset)
2. **Features used** (14 total):
   - Numeric: Age, MonthlyIncome, JobSatisfaction, EnvironmentSatisfaction, YearsAtCompany, TotalWorkingYears, StockOptionLevel, WorkLifeBalance, YearsInCurrentRole, DistanceFromHome, NumCompaniesWorked
   - Categorical (label-encoded): OverTime, JobRole, MaritalStatus
3. **Preprocessing**: categorical features label-encoded, all features standardized with `StandardScaler`
4. **Model**: a 3-layer feedforward network (14 → 32 → 16 → 1) with ReLU activations and dropout, trained with `BCEWithLogitsLoss` using a class weight (`pos_weight`) to correct for the imbalance
5. **Training**: stratified 70/15/15 train/validation/test split, with early stopping on validation loss (patience = 25 epochs) to prevent overfitting
6. **Evaluation**: accuracy, precision, recall, F1, ROC-AUC, and a full confusion matrix computed on the held-out test set
7. **Explainability**: permutation importance run on the test set to rank which features most affect model performance

## Usage

**1. Train the model**

```bash
python3 train_attrition.py
```

Trains the network, prints validation progress with early stopping, and reports final test-set metrics and feature importance. Produces `attrition_model.pth` and `hr_preprocessors.pkl`.

**2. Score an employee**

```bash
python3 terminal_app.py
```

Prompts for an employee's details (age, income, satisfaction scores, overtime status, job role, etc.) and returns a resignation risk probability with a recommendation.

**3. Generate chart images (optional)**

```bash
python3 generate_visuals.py
```

Produces `confusion_matrix.png` and `feature_importance.png` for reporting or sharing.

## Design Decisions

- **Fully local**: everything — training, inference, and preprocessing — runs on-device. No API calls, no internet dependency, no data leaves the machine.
- **Class imbalance handled explicitly**: rather than reporting a misleadingly high accuracy, the model is weighted and evaluated on metrics that reflect real-world usefulness (recall, F1, ROC-AUC).
- **Early stopping over fixed epochs**: prevents overfitting on a relatively small (1,470-row) dataset by monitoring validation loss rather than training for a fixed number of epochs.
- **Permutation importance over raw weight inspection**: gives a more reliable, model-agnostic view of which features actually matter, rather than relying on network weights that can be misleading with a non-linear model.

## Known Limitations & Future Work

- Precision is moderate (0.42) — roughly 6 in 10 employees flagged as high-risk turn out not to leave. Acceptable for an early-warning tool, but worth tuning further if false-positive workload becomes a concern (e.g. adjusting the classification threshold or using precision-recall curve analysis).
- Dataset is relatively small (1,470 rows) and specific to one company's HR practices — results may not generalize to other organizations without retraining on their own data.
- Potential next steps: k-fold cross-validation for more robust metrics, hyperparameter tuning (learning rate, hidden layer sizes, dropout rate), and a simple local GUI (e.g. Tkinter) as an alternative to the terminal interface.
